# 생성 이력 검색·페이지네이션 구현 계약

## 목적

생성 이력이 많아져도 사용자가 자신의 생성 결과를 빠르게 찾고 확인할 수 있도록
검색과 페이지 단위 탐색을 제공한다. 기존 `GET /generations` 목록 계약과 상세
조회 계약은 유지하고, 확장 기능은 별도 경로로 제공한다.

## 범위

- Service: 현재 로그인 사용자의 생성 이력만 검색·페이지네이션한다.
- Frontend: MyPage의 최근 생성 기록에 검색 입력, 결과 건수, 이전·다음 페이지를
  제공한다.
- 상세 결과를 펼치는 기존 동작과 상태·플랫폼·Credit 표기는 유지한다.

## API 계약

### `GET /generations/history`

인증이 필요한 사용자 전용 API다. 서버는 항상 인증된 사용자의 `user_id`로
필터링하며, 클라이언트가 다른 사용자의 식별자를 전달할 수 있는 검색 조건은
제공하지 않는다.

Query parameters:

- `q`: 선택, 공백을 제거한 검색어. 생성 `title` 또는 `question`에 대해
  대소문자·부분 일치한다. 비어 있으면 전체 이력을 대상으로 한다.
- `page`: 선택, 1 이상인 1-based 페이지 번호. 기본값 `1`.
- `page_size`: 선택, 1~50. 기본값 `10`.

응답:

```json
{
  "items": [],
  "page": 1,
  "page_size": 10,
  "total": 0,
  "total_pages": 0
}
```

`items`는 기존 `GenerationListItem`과 동일한 공개 필드만 포함하고, 생성일
내림차순·id 내림차순으로 정렬한다. 결과가 없으면 200과 빈 `items`를 반환한다.
`total_pages`는 `ceil(total / page_size)`이며 결과가 없을 때 0이다.

잘못된 `page`, `page_size`는 FastAPI 검증 오류(422)로 처리한다. `q`가 너무
길거나 공백뿐인 경우에는 빈 검색어로 취급한다(최대 200자만 사용한다).

## Frontend 계약

- MyPage 진입 시 1페이지를 조회한다.
- 검색어 입력은 300ms debounce 후 1페이지부터 다시 조회한다.
- 검색 중에는 이전 결과를 지우지 않고 로딩 상태를 표시한다.
- 검색 결과가 없으면 “조건에 맞는 생성 기록이 없습니다.”를 표시한다.
- 페이지 버튼은 전체 페이지가 1개일 때 숨기고, 현재 페이지·전체 페이지를
  함께 표시한다.
- 항목을 펼칠 때 기존 상세 API를 호출하며, 검색·페이지 이동 시 펼친 상세는
  닫는다.
- API 오류는 기존 `ErrorBanner` 경계를 사용하며 서버 내부 오류·민감정보를
  그대로 화면에 노출하지 않는다.

## 비범위

- 전체 텍스트 검색 엔진, 날짜 범위 필터, 정렬 옵션
- DB 마이그레이션 또는 생성 이력 보존 정책 변경
- 기존 `/generations` 및 `/generations/{id}` 응답 형식 변경

## 검증

- Service 테스트: owner scope, 검색(title/question), 정렬, page/page_size,
  빈 결과, 페이지 범위
- API 테스트: 인증, 응답 메타데이터, 잘못된 query, 다른 사용자 데이터 차단
- Frontend 테스트: 검색어·페이지 상태와 empty/loading/error UI
