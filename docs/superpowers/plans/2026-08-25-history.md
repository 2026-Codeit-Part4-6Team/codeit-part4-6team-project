# History search and pagination implementation plan

> **Execution rule:** implement this plan in the isolated `feat/history` worktree,
> test-first, and stop for review if the existing UI-polish contract must change.

## Goal

Add owner-scoped generation-history search and pagination without changing the
existing `/generations` list or detail response contracts.

## Tasks

1. **Lock the contract**
   - Add `docs/history_feature_contract.md`.
   - Confirm the new endpoint envelope and pagination defaults in tests.

2. **Backend tests first**
   - Add service tests for title/question search, owner isolation, deterministic
     ordering, page metadata, empty pages, and page-size validation.
   - Add API tests for authentication, query validation, and response shape.
   - Run only these tests and observe the expected failures before implementation.

3. **Backend implementation**
   - Add a paginated history response schema.
   - Extend `history_service.py` with a count query and bounded page query.
   - Add `GET /generations/history` while preserving `GET /generations`.

4. **Frontend tests first**
   - Extend API client tests for the new query string and response envelope.
   - Extend MyPage view tests for search, pagination, empty, loading, and error states.

5. **Frontend implementation**
   - Add typed paginated history API support.
   - Add debounced search and page controls to MyPage.
   - Reset selected detail when search or page changes.

6. **Verification**
   - Run targeted backend and frontend tests.
   - Run the repository-required full test commands if dependencies are available.
   - Review the diff for accidental changes outside history and report the stacked
     base (`origin/feat/ui-polish`) explicitly.
